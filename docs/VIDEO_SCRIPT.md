# 两分钟演示视频脚本

目标：用本地浏览器任务台，在两分钟内清楚展示“初始测试失败 → 智能体分析 → 人工批准修改 → 测试通过”，同时说明核心原理和安全措施。

## 录制前准备

1. 提前完成真实模型联调，并至少重复成功三次。
2. 重置演示项目：

```powershell
python examples\reset_inventory_demo.py
```

3. 在录制前启动工作台，确认真实模型已经配置好：

```powershell
python -m coding_agent web --workspace examples\inventory_reservation --env-file .env --no-open
```

4. 在访客/无痕窗口打开终端给出的本机地址，再使用全屏模式；隐藏书签栏、账号头像、下载记录和通知。
5. 关闭聊天软件、邮件和系统通知。录屏中不要打开 `.env`、GitHub 个人页或带完整用户目录的终端。
6. 确认页面顶部只显示工作区名称 `inventory_reservation`，不显示完整电脑路径。

## 时间安排和讲解词

### 0–15 秒：说明项目和界面

画面停留在本地任务台。输入框已经自动填好演示任务。

讲解：

> 这是一个用 Python 从零实现的轻量编程智能体，没有使用 Agent 框架。左边按顺序记录执行步骤，右边显示文件内容、修改差异和命令输出。

### 15–35 秒：启动并看到真实失败

点击“开始任务”。智能体提出第一次运行测试时，检查参数后点击“允许本次运行”；选择对应的命令结果，让右侧显示失败测试。

讲解：

> 这个库存项目要求一次订单要么全部预留成功，要么库存完全不变。现在有一项测试失败，因为程序在发现后续商品不足前，已经扣除了前面的商品。

### 35–95 秒：分析、审批修改、重新测试

让时间线继续运行。只读步骤不需要操作；出现文件修改时，在右侧检查文件名和差异，再点击“允许本次修改”。出现最终测试命令时，再单独批准。模型等待时间可以剪辑或加速，但保留三种关键画面：失败输出、修改审批、通过输出。

讲解：

> 智能体先通过只读工具了解项目。修改文件和运行命令有副作用，所以必须逐项批准。每次工具结果都会返回给模型，模型再决定下一步。

### 95–112 秒：展示结果

保留页面中的“任务已完成”摘要和统计；点击最后一次命令结果，右侧显示测试全部通过。

讲解：

> 修复后，两项测试都通过。智能体没有修改测试，而是把处理过程改成先检查全部库存，再统一扣减。

### 112–120 秒：一句话总结

短暂切换到本地的 `docs/architecture.png`。

讲解：

> 核心循环、工具执行、上下文管理和错误处理都由项目自行实现，并加入了路径限制、密钥保护和重复调用停止机制。

## 导出前检查

- 总时长不超过 2 分钟。
- MP4 格式，文件不超过 200 MB。
- 画面和声音中没有姓名、学校、账号头像、个人主页、通知或 API Key。
- 工作台只显示相对文件名和工作区名称，没有完整用户目录。
- 关键文字在普通笔记本屏幕上仍清晰可读。
- 从头播放一次，确认声音、画面和加速片段都正常。
