# 两分钟演示视频最终脚本

目标成片时长：1 分 50 秒到 1 分 55 秒，至少预留 5 秒余量。视频要证明三件事：这是真实编程任务；Agent 会根据工具结果继续判断；有副作用的操作受到人工控制。

## 最稳妥的录制方式

先完整录下一次成功操作，不要同时讲解。剪掉模型等待时间，保持事件顺序不变，再按下面的逐字稿后期配音。不要为了追求“一镜到底”承担超时、口误或模型等待过长的风险。

## 录制前准备

1. 在仓库根目录恢复演示 Bug：

```powershell
python examples\reset_inventory_demo.py
```

2. 启动本地任务台：

```powershell
python -m coding_agent web --workspace examples\inventory_reservation --env-file .env --no-open
```

3. 在干净的浏览器窗口打开终端给出的本机地址。任务会自动填写，不需要在视频里打字。
4. 按 `F11` 全屏，关闭书签栏、通知和聊天软件；只录浏览器，不录终端、`.env` 或 GitHub 页面。
5. 先完整演练至少三次。首次和末次命令只批准明显的测试命令；文件修改只应涉及 `shop/service.py`。

推荐任务内容：

```text
请修复当前项目中的失败测试。业务要求：如果任何商品库存不足，整个预留必须失败，任何库存都不能变化。不要修改测试或降低断言。请先检查项目并运行测试，只做必要修改，最后再次运行测试确认全部通过。
```

## 成片时间轴、操作和逐字稿

### 00:00-00:13 - 介绍功能

画面：停留在初始任务台，鼠标依次指向任务、左侧执行记录和右侧步骤详情。

讲解：

> 这是我用 Python 从零实现的编程智能体，没有使用 Agent 框架。它能查看、搜索和修改文件，也能运行测试等本地命令。

### 00:13-00:27 - 解释核心循环并开始

画面：指向任务内容，点击“开始任务”。等待片段后期剪掉。

讲解：

> 核心是一个循环：模型选择工具，本地程序校验执行，再把结果返回模型，直到任务完成。模型负责判断，程序控制实际操作。

### 00:27-00:39 - 说明测试案例

画面：保留几项读取记录，等待第一次命令审批。

讲解：

> 案例是多商品库存预留：只要一种商品不足，整次操作就应失败。我要求它不改测试，只修业务代码。

### 00:39-00:52 - 批准首次测试

画面：审批出现后停两秒，确认预览是测试命令，再点击“允许本次运行”。

讲解：

> 读取可以自动执行；命令和修改会改变本地状态，所以逐项批准。这里确认是测试命令，我允许运行。

### 00:52-01:04 - 展示真实失败

画面：点击左侧第一次未成功的命令结果，让右侧显示失败测试。

讲解：

> 测试出现一项失败：旧代码先扣了键盘，之后才发现鼠标不足，破坏了整体不变。

### 01:04-01:15 - 展示继续分析

画面：保留模型请求、读取文件等两到三项记录；等待时间跳切。

讲解：

> 失败结果会返回模型，它继续读取代码并定位原因，而不是一次性猜答案。

### 01:15-01:32 - 检查并批准修改

画面：文件修改审批出现后，指向 `shop/service.py` 和差异，再点击“允许本次修改”。

讲解：

> 修改前页面展示差异。我确认它只改 service.py：先检查全部库存，再统一扣减，避免部分修改。

### 01:32-01:43 - 再次批准测试

画面：最终测试审批出现，确认命令后点击“允许本次运行”。

讲解：

> 修改后它再次请求运行测试。审批只对本次操作有效，所以我再次确认。

### 01:43-01:55 - 展示成功并总结

画面：点击最后一次成功的命令结果，展示 `Ran 2 tests` 和 `OK`，最后停留在“任务已完成”和统计信息。

讲解：

> 现在两项测试全部通过。系统还限制路径、轮数和重复调用，并保护密钥，让过程可观察、可控制、可停止。

## 剪辑规则

- 只剪模型等待时间，不改变事件先后顺序，也不要伪造结果。
- 保留三个完整证据画面：首次测试失败、修改审批差异、最终测试通过。
- 鼠标点击和审批不要加速；等待片段直接跳切比倍速更清楚。
- 不需要展示复杂架构图。任务台的执行记录已经能对应“模型 -> 工具 -> 结果 -> 模型”的循环。
- 不使用花哨转场、AI 配音或背景音乐；普通跳切、本人配音和少量字幕更自然。

## 必须重录的情况

- 模型要求修改测试文件、运行无关命令或大范围改动。
- 最终没有出现两项测试全部通过。
- 画面出现姓名、学校、GitHub 账号、完整用户目录、通知或 API Key。
- 成片达到或超过 2 分钟。

## 导出检查

- MP4，1080p，30 fps，文件不超过 200 MB。
- 建议成片控制在 1 分 55 秒以内。
- 从头播放一次，确认配音、字幕和画面一致。
- 最终 ZIP 里只放 `README.txt` 和视频，不放源码或 `.env`。
